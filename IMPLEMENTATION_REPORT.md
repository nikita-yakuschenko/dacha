# Реализация «просто дача»

## Последние изменения по указаниям пользователя

Добавлены Dockerfile, .dockerignore и compose.yaml; Next.js output standalone. Docker-сборка и запуск Linux-контейнера проверены: HTTP200 главной и изображений, работа next/image и поп-апа, healthcheck healthy, непривилегированный uid1000. Инструкция: docs/DOCKER.md. Dev остаётся на3000.

Hero использует новое изображение пользователя на ширину контейнера: дом сдвинут вправо, переход светлой маски перенесён вправо. На мобильном сняты внутренние боковые отступы, сохранены внешние поля контейнера; на320/360/390/430px горизонтальной прокрутки нет.

Актуальная структура: лендинг с крупными поп-апами трёх проектов. Отдельные `/projects/[slug]` удалены. Карточки открывают Radix Dialog без смены URL; доступны переход между моделями, фокус внутри окна, закрытие Esc/кнопкой и возврат фокуса. Изображение, характеристики, опции и форма находятся внутри диалога. Код диалога загружается только при открытии.

Dev работает через `npm run dev` на `http://127.0.0.1:3000` с Fast Refresh. Миниатюры hero временно отключены JSX-комментарием; компонент и три отдельно сгенерированных изображения 4×5/4×6/5×6 сохранены. У преимуществ увеличены текст и иконки: лист, кошелёк, инструменты Tabler. Удалены подписи поверх изображений по прямому указанию пользователя. Исторические сведения о страницах проектов и исходных скриншотах ниже относятся к первой версии.

Текущие скриншоты диалогов: `.impeccable/review/project-popup-1440.png` и `project-popup-390.png`.

После перехода на поп-апы выполнены 3 актуальных UI-теста (18,2с): все девять ширин, отсутствие перехода с лендинга, правильная модель и переход между моделями, закрытие и возврат фокуса, опции, демоформа, клавиатурные вкладки и axe WCAG AA. Все прошли. Lint и TypeScript также прошли. Поп-ап хранит намерение открытия до загрузки компонента, поэтому ранний клик не теряется.

Дата: 4 ноября 2026. Работа выполнена в текущем репозитории `C:\dacha`.

## Результат

Работающий локальный сайт на Next.js 16.4.5 App Router, React 19.3.1, TypeScript strict, Tailwind CSS 4.3.4. Главная и страницы проектов — Server Components; клиентские границы ограничены выбором, формой и вкладками. Формы: React Hook Form 7.91 + Zod 4.6.7. Inter Variable 5.3.0 поставляется локально. Все версии закреплены в package.json и package-lock.json.

Маршруты:

- `/` — десять секций: hero, три проекта, комплектация, технология/сезонность, производство, расчёт, логистика, пять этапов заказа, FAQ, свой размер.
- `/projects/dacha-20`, `/projects/dacha-24`, `/projects/dacha-30` — изображение, наружный контур, характеристики, опции, компактная форма. На desktop — три колонки, на мобильном — последовательный поток и нижняя панель расчёта.
- `/contacts` — честное состояние отсутствующих контактов, реквизитов и документов.
- Страница 404 и метаданные каждого проекта.

Публичного размещения и домена нет. Сайт доступен через локальный production-сервер `http://127.0.0.1:3000`; повторный запуск: `npm run build`, `npm run start`. Разработка: `npm ci`, `npm run dev`.

## Компоненты и взаимодействия

Локальные shadcn/ui получены официальным CLI shadcn 4.23.0: Button, Input, Label, Tabs; исходный код контролируется в `src/components/ui`. Адаптированы токены, типы и контраст; иконки — только Tabler. Ненужный Dialog удалён, для мобильной формы использована разрешённая брифом отдельная секция.

Повторно используются Header/Footer, HouseImage, Plan, FormatSwitch, CalculateButton, CalculationForm. SelectionProvider сохраняет только enum проекта, enum формата и boolean террасы. Путь проекта имеет приоритет над сохранённым ранее размером. Личные данные, населённый пункт и свободный текст в localStorage не пишутся.

Главный расчёт: формат → проект/свой размер → населённый пункт и срок → телефон ИЛИ Telegram, необязательное имя и отдельное непредвыбранное согласие. Возврат сохраняет поля в памяти. Карточка передаёт конкретный проект и текущий формат; свой размер открывает соответствующий шаг. Монтаж по введённому адресу не гарантируется. Есть валидация, сообщение деморежима, подготовленные состояния отправки/ошибки/подтверждения и защита от повторного submit.

Backend отсутствует: по умолчанию кнопка проверяет поля и сообщает, что заявка не отправлена. Нет фиктивного успеха или обещания обратного звонка. Политика не подменена заглушкой ссылки. Реальная отправка включается только при наличии endpoint и URL документов; успешное состояние требует подтверждения сервера `{accepted:true,id}`. Такой backend и интеграционные сценарии с ним не проверены. Контракт и условия подключения: [docs/INTEGRATION.md](docs/INTEGRATION.md).

Обезличенные события типизированы в `src/lib/analytics.ts`; внешняя аналитика не подключена. События не содержат введённых пользователем данных. UTM предусмотрены в payload только для последующей реальной интеграции.
