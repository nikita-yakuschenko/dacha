# Запуск и приём заявок

Node.js >=20.9; проверено на Node 22.15 / npm 11.9 / Windows. `npm ci`, `npm run dev`. Production: `npm run build`, `npm run start`. Проверки: `npm run lint`, `npm run typecheck`, `npm run test:ui`. Для UI-проверок один раз `npx playwright install chromium`.

Страницы генерируются статически средствами Next.js. `next start` обслуживает также оптимизацию локальных изображений. Backend/CRM в пакете нет; сайт по умолчанию работает в деморежиме, без отправки контактов. Состояния загрузки, ошибки и реального подтверждения подготовлены, но требуют интеграционных испытаний с выбранным сервисом.

Для подключения нужен настоящий endpoint, юридические документы и реальный origin в `.env.local` по `.env.example`. Отправка включается только когда endpoint и policy URL заполнены. Публичные переменные требуют пересборки. Токены и секреты запрещено помещать в NEXT_PUBLIC_*: сторонний сервис должен предоставлять публичный защищённый серверный обработчик либо нужно реализовать собственный серверный маршрут.

Контракт POST: JSON `{project, format, terrace, custom, location, timing, channel, contact, name, consent, attribution}`. Заголовок `Idempotency-Key` стабилен для повторной попытки после сетевой ошибки. Только ответ HTTP 2xx с `{accepted:true,id:"реальный номер"}` включает подтверждение приёма. При ошибке/таймауте поля не очищаются; повторный submit во время запроса блокируется. На сервере обязательны повторная валидация, consent и версия документов, ограничение частоты, дедупликация, идемпотентность и проверка фактической доставки заявки. Если меняются данные после сетевой ошибки, перед production согласуйте семантику идемпотентности обработчика.

В localStorage хранится только `dacha:selection`: enum проекта, enum формата и boolean террасы. Контакт, имя, населённый пункт и свободный текст — только в памяти формы. Событие `dacha:analytics` содержит только тип действия, enum проекта/формата и номер шага; адаптер аналитики не подключён. UTM читаются только при реальной отправке, не записываются в localStorage. Рекламные метки должны быть свободны от персональных данных.

До production: подключить и проверить приём заявок; опубликовать реальные документы и реквизиты; подтвердить планы, цены, спецификации, сроки, географию и условия гарантии; заменить общий концептуальный образ реальными фасадами. После готовности изменить robots в `src/app/layout.tsx`, указать реальный metadataBase/origin и подготовить sitemap. Хостинг и домен не настроены: задача выполнена в текущем репозитории.
